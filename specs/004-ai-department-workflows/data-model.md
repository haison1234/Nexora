# Data Model: Workflow Capability Bridge

**Feature**: `004-ai-department-workflows`
**Status**: T001–T004 are implemented. Invocation persistence, pre-dispatch reservation, encrypted Agents-owned input staging/resolution, retry linkage, cancellation intent, authority-revocation detection, and result delivery authorization have implementation slices. Agents has a durable child outcome outbox with owner-generated sequence IDs and a verified child snapshot boundary. Recovery before child persistence, native stop proof, and live verification remain open behind owner guarantees.

## Records

| Record | Fields | Invariants |
|---|---|---|
| WorkflowCapability | id, projectId, memberId, workflowId, purpose, inputSchemaRef, enabled, version, timestamps | Same project; selection grants no execution permission. Pin published version and input-schema identity. Publication changes require revalidation before future invocations. |
| WorkflowCapabilityRevision | id, projectId, capabilityId, version, purpose, publishedVersionRef, triggerCompatibilityRef, inputSchemaFingerprint, enabled, changedById, createdAt | Immutable snapshot of a coordinator-accepted capability configuration. Invocation references its version. |
| WorkflowInvocation | id, projectId, workId, attemptId, memberId, capabilityId, capabilityVersion, claimGeneration, requestId, ownerInvocationKey, inputHash, inputsRef, expectedWorkflowVersion, actualWorkflowVersion?, ownerExecutionRef?, dispatchState, childState, version, timestamps | Unique attemptId/requestId. Match the current attempt, live claim, selected capability revision, and published workflow before dispatch. `claimGeneration` currently uses the attempt ordinal because the schema allows one claim per attempt. |
| InvocationReceipt | invocationId, ownerEventId, ownerSequence, ownerExecutionRef, retryOfExecutionRef?, receivedAt | Duplicate events are no-ops. A new execution is accepted only when its retry parent matches the current execution. Late events from known superseded executions cannot update current work. |

Unacknowledged events remain pending for reconciliation. The sequence ID is generated by the native owner database. |

## State rules

Dispatch state is pending, acknowledged, unknown, or rejected. Child state is pending, running, waiting, retrying, succeeded, failed, cancelled, or unknown. These are projections of n8n-owned state, not a new execution engine.

Store input references in owner-authorized storage, not in general activity. Agents stages the encrypted payload before dispatch and resolves it by project, invocation, reference, and hash. Persist invocation-key intent before dispatch. The owner must durably accept and locate the same key. A new request ID means a deliberate new invocation and requires current attempt access. Recovery before native child persistence remains open.

Keep cancellation-request time separate from child outcome. Native retries keep their native execution linkage. A retry emits a linked `retrying` event followed by its current lifecycle state; the retry label does not claim that the child is still running. Workflow success does not directly mark a business work item done.

## Schema and ownership

Add capability/invocation tables under the department persistence directory and use database migrations. Agents owns native execution lookup and outcome outbox records. Reconciliation may acknowledge a retained child only after its invocation ID, input hash, and pinned workflow version match. No copied credentials, workflow graph, prompts, or full result payloads are stored here. Execution/result retention remains with n8n; unavailable references produce an unavailable label.

## Field Conventions

Identifiers are opaque strings and are compared within their project context. Persisted timestamps use the owning database timestamp convention; JSON timestamps use RFC 3339 UTC. Versions and sequences are nonnegative integers; record versions start at 1. Nullable fields use explicit null in responses. Reject unknown command fields and invalid enum values through shared DTO validation.

## C5 Workflow bridge — Approved 2026-11-03

### Approved C5 model amendments

Capability revisions pin publication, trigger compatibility and input schema identity. Invocation records pin attempt, claim generation, capability revision, idempotency key, expected/actual workflow version and owner execution reference. Reservation verifies the parent execution ID from the persisted claim. The SDK run ID is only a correlation value; it is not an AgentExecution ID. The native child owner writes ordered state events to its outbox and retries delivery. Keep full payloads and credentials with n8n owners.

The model is approved. Exact-version owner acceptance, child outcome delivery, encrypted input-reference resolution, retry linkage, cancellation intent, and result delivery authorization have focused implementation slices. The Agents owner verifies project, invocation, input hash, and pinned version before retrying stop for an accepted child.
